Cimentación: los sistemas

Lo que no se ve y aguanta todo lo demás. Herramientas internas para que un equipo pequeño gestione muchos proyectos a la vez, con la IA trabajando dentro y una persona decidiendo.

NotionPilot

Panel de operaciones propio · con mi socio

Problema
Clientes, tareas, documentos y decisiones repartidos entre WhatsApp, notas y hojas de cálculo.
Solución
Un panel único por proyecto con estados, fechas y feed de actividad, y un servidor MCP para que la IA lea y escriba con permisos limitados. Cada sesión de trabajo queda registrada al abrir y al cerrar.
  • 24proyectos
  • ~600tareas
  • 537commits

React · TypeScript · Supabase · MCP · VPS propio

ERP hub

El centro que conecta los demás productos

Problema
Cada producto tenía su base de datos y sus facturas; el mismo cliente, cinco veces.
Solución
Un ERP multiempresa que hace de hub: los proyectos se conectan por REST y webhooks (la tienda reindexa su catálogo cuando cambia el ERP). Facturación con libro inmutable, roles y aislamiento entre empresas.
  • 15migraciones de la auditoría de seguridad (oct-2026)

Supabase · PostgreSQL con RLS · Next.js · webhooks

Runner y agencia de agentes

IA que trabaja de noche, con una persona que aprueba

Problema
Mucho trabajo repetible (revisar, documentar, pequeñas mejoras) y nadie para hacerlo.
Solución
Un ejecutor diario que coge tareas aprobadas en NotionPilot, trabaja en una rama aislada de cada repositorio y deja un pull request para revisar. Tiene un tope de gasto por tarea y devuelve la tarea con el motivo si algo no cuadra. Detrás hay una agencia de agentes con 18 roles sobre Claude y modelos locales.
  • ~7.200eventos a la semana
  • 20proyectos que vigila

Node · Claude · Ollama · systemd · Telegram

PresupuesYa

SaaS de presupuestos para reformistas

Problema
El reformista presupuesta de noche, en Excel, y no sabe si una obra le ha dejado margen.
Solución
Partidas con sus precios, PDF con su logo, firma del cliente en el móvil y margen real por obra. Importa y exporta BC3, el formato del sector, validado con bases de precios reales (BCCA y CAR).

React · TypeScript · Supabase · despliegue automático con GitHub Actions

Cubierta: cómo trabajo

Lo mismo que en una obra: no se empieza sin proyecto ni se entrega sin medir.

  1. Leer el negocioDatos medidos: reseñas, local, catálogo, búsquedas. Nada supuesto.
  2. Decidir por escritoLas decisiones van escritas antes de construir, para poder discutirlas.
  3. ConstruirCon IA como herramienta y una persona dirigiendo y revisando.
  4. MedirRendimiento, Search Console, ventas. Si no se mide, no se entrega.
  5. RegistrarTodo queda en el panel. Lo que se aprende en un caso sirve para el siguiente.
